01 · The setup

One number, two walls

Each weight has a rounding variable h, a number between 0 and 1. It decides whether the weight rounds down or up:

quantized weightŵ = s · ( ⌊w/s⌋ + h )   h must end at 0 or 1

During training h can sit anywhere in between — this one sits at 0.6. That's a guess, still being tuned. By the end it has to be touching a wall.

The optimizer's entire job: walk this ball to one of the two walls — and pick the right wall.

IDEA 1 / 4 — WALK

Nudge it a little, every step

the update — done every steph ← h − η · sign(m)

η is the size of one nudge (small — 0.05 here). sign(m) is the direction, just +1 or −1. Each step, h moves one small fixed step left or right. Repeat, and the number walks to an end:

0.60

Same-size step every time — only the direction is decided. A ball at 0.3 would walk the other way: 0.30 → 0.25 → … → 0.

02 · Inside the direction

Two forces add into one push, g

the push on one weightg = grec + λ(t) · gate · (−sign(h − 0.5))

Force 1 — tuning (g_rec): keep the layer's output accurate. It pushes h toward whatever value reconstructs best, and it's noisy — it jitters with every calibration minibatch. Where this number actually comes from is the next two slides.

Force 2 — the pull: push h toward its nearest wall. The factor −sign(h − 0.5) just means "point at the closest end".

02 · The tuning force

Where g_rec comes from

Run the same calibration input X through the block twice: once with the original full-precision weights, once with the quantized ones. Compare the outputs.

reconstruction loss & its gradient (one linear layer)L = ‖ŷ − y‖²  →  g_rec = ∂L/∂h = 2s · Σ (error · input)

Only one thing in ŷ depends on h, and linearly: ŵ = s(⌊w/s⌋ + h), so ∂ŵ/∂h = s. The gradient is just the output error times the input it rode in on, scaled by the step size s. If raising h would shrink the block's error, g_rec comes out negative — and descent raises h.

02 · The tuning force, with numbers

One weight, one input: g_rec by hand

Setup: scale s = 0.1, original weight w = 0.53 → ⌊w/s⌋ = 5, so ŵ = 0.1·(5 + h). One calibration input x = 2, full-precision output y = 0.53·2 = 1.06. Current h = 0.6.

  1. ŷ = 0.1·(5 + 0.6)·2 = 1.12 — the quantized output overshoots.
  2. Error: e = ŷ − y = 1.12 − 1.06 = +0.06. Loss L = e² = 0.0036.
  3. g_rec = 2·e·(s·x) = 2·0.06·0.2 = +0.024 — positive, so descent lowers h. Correct: the output was too big.
  4. Where does the force vanish? e = 0 at h* = 0.3 — exactly the true remainder w/s − 5 = 0.3. Alone, tuning just recovers round-to-nearest.

So why learn h at all? In a real layer thousands of weights share each output error. Weight A's best h can shift off its remainder to cancel weight B's rounding error — that compensation is the entire win of adaptive rounding.

And the noise? Each minibatch is a different x, so g_rec jitters step to step — the jitter that momentum smooths on the next slide. (In the simulation, all of this is stood in for by a spring: g_rec ≈ curv·(h − h*) + noise.)

02 · The missing link

m is a running average of recent g

each step, in this order① g = forces   ② m ← 0.9·m + 0.1·g   ③ h ← h − η·sign(m)

Keep 90% of the old m, fold in 10% of the fresh g. m becomes a memory of recent pushes: opposite jitters cancel inside the average, so sign(m) stays a stable direction.

Step 2's push swung negative — but m stayed positive, so the ball never flipped direction. One bad minibatch can't jerk the walk around.

IDEA 2 / 4 — SCHEDULE

λ(t) — the pull starts near zero and turns up

Why not round 0.6 → 1 instantly? Because 0.6 is a guess still being tuned; commit too early and you lock in the wrong wall. So the pull is a dial: off at the start, strong by the end. Drag training forward and watch the floor's middle rise into a hill:

IDEA 3 / 4 — GATE

Push the decided, spare the undecided

Confidence c = |2h − 1| measures how decided a weight looks: 0 on the fence, ~1 near a wall. The gate scales the pull by it:

gate — between 0.15 and 1.0gate = 0.15 + 0.85 · σ( 8 · (c − θ(t)/2) )

IDEA 4 / 4 — LATCH

Arrive, and a latch clicks shut

Tuning never fully stops — one noisy update could bump a weight at 1 back to 0.98 and set it wandering. So when confidence crosses θ(t), the weight is pinned to its wall. A stray opposing nudge? Ignored — the counter decays. A sustained stream of ~30 opposing steps? The latch releases: real accumulated evidence, and rare.

This replaces the straight-through estimator's behavior, where a committed weight can chatter back across 0.5 on any noisy minibatch. Hysteresis makes commitment sticky but not irreversible.

03 · All four ideas, one update

Every word is a symbol here

gg_rec = 2s·Σ(error · input)TUNING — block output error, backed through ŵ = s(⌊w/s⌋+h)
cc = |2h − 1|how decided this weight looks (0 = fence, 1 = wall)
3gate = 0.15 + 0.85·σ(8·(c − θ(t)/2))GATE — whisper for the undecided, firm for the decided
2g = g_rec + λ(t) · gate · (−sign(h − 0.5))SCHEDULE — tuning + pull-to-nearest-wall, dialed up by λ(t)
mm ← 0.9·m + 0.1·gmemory — running average turns noisy pushes into a persistent lean
1h ← h − η(t) · sign(m)WALK — one fixed-size nudge in the direction of the lean
4if c > θ(t): pin h to its wall · ~30 opposing steps in a row: releaseLATCH — commitment is sticky, undone only by sustained evidence

Two schedules run underneath: λ(t) ramps up (pull harder) while θ(t) anneals down (accept commitments from more weights). Their crossover is when the layer visibly polarizes.

03 · One weight, one step, real numbers

Step 2000 of 5000 · a weight at h = 0.88

Schedules here: θ(t) = 0.905, λ(t) = 0.46, η(t) = 0.003. Momentum carried in: m = −0.25. Sign convention: negative g means "raise h".

  1. c = |2·0.88 − 1| = 0.76 — well off the fence, leaning to wall 1.
  2. gate = 0.15 + 0.85·σ(8·(0.76 − 0.45)) ≈ 0.93 — wide open.
  3. Pull: 0.46 · 0.93 · (−1) = −0.43. This minibatch's tuning: g_rec = +0.13. Total g = −0.30.
  4. m = 0.9·(−0.25) + 0.1·(−0.30) = −0.255 — the lean stays negative.
  5. sign(m) = −1 → h ← 0.88 + 0.003 = 0.883. One nudge closer to wall 1.
  6. Latch check: c = 0.766 < θ = 0.905 → not pinned yet. But θ(t) is annealing down while h drifts up — they meet in a few hundred steps, and click.

Note what the sign update bought: the pull never had to out-muscle tuning — only win the sign of the average. A modest λ suffices, and the step stays exactly η no matter how large g gets.

Recap

Four ideas — and what each replaces in TesseraQ

1

WALK — h ← h − η·sign(m). Fixed-size nudges; momentum turns noisy pushes into a steady direction.

Replaces the Adam inner loop: sign steps make polarization timing schedule-controlled, not curvature-controlled.

2

SCHEDULE — λ(t) turns the pull-to-nearest-wall up from ~0 to dominant. Tune first, commit later.

Replaces AdaRound's fixed regularizer with an annealed force routed through the loss.

3

GATE — pull scaled by confidence. Decided weights pushed home; fence-sitters left to gather evidence.

Replaces the PAR loop's discrete "freeze the top-p% every K steps" with a smooth per-weight version.

4

LATCH — cross θ(t) and you're pinned; only ~30 consecutive opposing steps release you.

Replaces the straight-through estimator's chatter with hysteresis: sticky, not brittle.

One pass, ~5000 steps — the hard rounding is already done when training ends. That's CASR.
